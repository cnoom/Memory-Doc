**护甲/格挡不是必须单独凑齐的一套流派**，而是任何主轴都可选的辅助组件（N07皮甲、S21息笔、X46余盾、X49反制、X50虎魄盾等）。不再追求“六套纯系各自独立成型”；玩家可选择单轴强化、双轴混搭，或者用格挡防御支撑任意进攻组合。

### 混搭最低可行性（设计约束）

- **一张启动牌应能独立发挥基础价值**，没有完整流派时仍能替掉弱起始牌。任意两套机制的组合不能要求收齐大量特定稀有卡才开始有效。
- 第二章验证 **主轴2–3种机制件＋副轴1–2种机制件** 的可得性和战斗价值；这是待测的样本设计目标，不是保证任何随机路线一定能拿到。
- 示例A：**力量＋流血**——开篇/挫锋施血，轻刃/三拍/并击多段输出，鲜红涂刃补充流血。
- 示例B：**中毒＋多段附伤**——毒雾/毒针建立毒层，渗毒斩的多段独立伤害包在力量下放大。
- 示例C：**蓄步＋力量连击**——挪页/移页签移动，游刃/穿书增加伤害或额外攻击段，再用力量提高每段收益。
- 示例D：**翻回成长＋防御**——复习/旧识的回访收益叠加皮甲的护甲启动，再由探卷或其它攻击牌兑现。
- 示例E：**流血＋中毒**——划痕/承接维持流血，毒血互换/毒雾提供中毒，绝唱以多负面状态终结。对多轴兑现牌必须检查不可变快照，不能在本次配对中使用本次新施加的负面状态为另一实例增伤。

## 3. 保留的V7.2机制与待落地语义

1. **同名配对＋同一不可变快照**：同名两实例各执行一次；冻结配对前条件和各自实例成长，禁止A先施毒后让B本对条件变为“已有毒”。力量依旧加每段直接攻击和每包独立附加伤害，不加中毒的定时伤害。
2. **翻回成长**：学者在真实正面→背面时使该实例可强化的有益固定数值+1，最多2层，离场清零；S04探卷仍固定「造成2段2点伤害。[翻开] 临时伤害+1。」。详情/入场视觉预览不算翻开或翻回。
3. **蓄步（无上限）**：每个背面实例实际移动一个格位蓄步+1，无论敌我造成；交换双方各+1。确定为**按真实翻开兑现窗口**：`PendingSteps`累计自上次真实翻开之后的步数，翻开瞬间冻结至`FlipLockedSteps`供同次卡牌和遗物使用，然后`PendingSteps=0`；`LifetimeSteps`记录本场历史总移动（不直接参与同次兑现），`HasMovedThisBattle`支持「曾移动」条件。三者均不设硬上限。重复翻开只根据**新窗口**刷新同来源加成，不复制旧步数；翻回本身不增加蓄步。
4. **移动操作**：玩家只选合法背面来源牌，再选来源旁仅显示的上/下/左/右合法方向；相邻空格直接移动，与相邻合法背面牌交换；不能选中病毒、正面或封锁牌，不能远距离移动。每实例每次触发最多一次移动请求，可取消/跳过，X37不再拥有远距交换。
5. **护甲/格挡**：护甲不直接吸伤；敌人一次完整行动结束后清旧格挡，再按护甲层数产生新格挡（遗物保留另行定序）；非攻击意图同样按完整行动一次触发；死亡中断不补发。
6. **流血**：真实有效的每段直接攻击触发当前流血层数的附加伤害包，之后层数-1；不递归。S28可帮助补层，多段可能迅速消耗现有流血，须对账。
7. **中毒**：按现行动条满相关事件造成层数伤害，层数不自然衰减；不能在本轮额外加入主动消耗中毒换收益的支付机制。遗物R21旧中毒支付触发无实际来源，列为适配阻塞，不得假称已生效。
8. **[消耗]属性**：暂存19种正式候选（全历史池21种）；是否最终保留机制及一次性卡强度仍待审。不恢复主动支付生命/格挡/护甲/中毒等状态的旧方案。

## 4. 遗物与敌人同步范围

- 原V2遗物36件保留**独立历史ID**，本轮先做语义筛选：**R07火绒盒、R20冷焰石、R31熔芯**涉及灼烧/冰冻，V7.2正常新Run中应同步**暂缓投放**，但不删除旧存档兼容；其余遗物不代表自动全部兼容或无需平衡。
- **R21酸蚀漏斗**原「玩家效果消耗≥2中毒」与当前卡池的状态支付取消冲突；建议改为「每周期首次敌方拥有中毒≥3且实际受到中毒伤害后，获得2格挡」，不直接产永久护甲（仅策划建议，需验收）。
- **R05笔记本、R10旧扣环、R18思维导图、B03记忆王冠**的护甲产出应按新版长期产格挡重新估价；若触发频繁，优先改为格挡或限次，不把旧永久护甲收益照搬。
- **R24/R25/R32**等蓄步读取遗物，读取统一的`FlipLockedSteps`，不清空他人的计数、不从历史累计值重复兑现。学者是**真实翻回强化**，旧22「翻开强化」文字属于历史协议冲突，迁移时必须改。
- V7.2正常奖励池不生成14张火冰卡，也应避免遗物/敌人作为玩家不可选的强制火冰构筑资源。敌人本身原本具有的火冰异常可以为旧敌人兼容保留，但不能无提示制造对玩家不可得的唯一流派启动件。
- 遗物V2既有实现与正式投放版本是独立协议：**不能从策划文档推断已修改Unity或切换正式遗物池**。
