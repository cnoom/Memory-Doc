## 1. 用户确认的设计裁定

本次用户逐轮确认：保留战斗 V05 蚀刻版画风格；奖励页不使用“交换/加入”两个主入口；奖励页三选一选中之后点击统一的“确认选择”按钮；若牌库未满则直接获得新卡并结束，若牌库已满则**直接打开交换页**，中间不得再出现“牌库已满，是否交换”的询问层；交换页可返回奖励页，或选择一张旧牌后确认交换。

最终确认的交换视觉：扩大的居中骨白纸面弹层，左侧一张大幅“将获得的新卡”，右侧**4 列 × 2 行**可视旧牌缩略卡（默认 8 张/页），底部左右翻页与页码，页面底部“返回奖励页”与“确认交换”；雾蓝描边表明已选择的旧牌。副界面遮暗原奖励页，保持原选中候选不变。视觉参考为 2026-11-09 对话中最后一张已获用户“可以了”的大版交换稿（1672×941 组合预览）；它仅是**布局/材质/视觉密度参考**，不是运行时底图和卡牌数据正本。截图若另行存档，必须保留原始 SHA-256 以避免误认不同版本：4bb6f8eb029dc16f59cf09fc6363727e3e2c61f988139b7ff43a09a77a7745cf。

## 2. 风格边界：不偏离 Battle V05

- 基调：残页秘境；骨白 #EDE8DC、场景墨黑 #202326、炭灰 #343A3D、次纸灰 #D1CBBD、雾蓝 #83B0C1；朱红 #B94D3E 只用于风险/伤害，不用高饱和金色重做按钮。
- 版画景深、轻纸纹、页面错层、细边框、装订/批注/折角集中于边缘；**中央信息区保留留白**。不采用上一轮被否决的华丽金属桌游卡框/皮革卷轴/能量徽章。
- **复用现有正式卡框、卡图、字体规范与 B03 按钮**。所有卡牌名称、类型、稀有度、说明、牌库统计及状态标签必须 UI/TMP 动态生成。未独立完成的卡插画沿用工程当前明示的临时映射，不依据示意图反向改卡牌数据。
- 概念图出现过的“能量费用”“抽手牌”“回到手牌”“额外加入按钮”、虚构章节/HP/金币等属于错误示例，**均不进入功能实现**。必须使用现行 14/15/16 和运行时数据。

## 3. S05 主奖励页交互

| 状态 | 主按钮 | 行为 |
| --- | --- | --- |
| 尚未选候选卡 | “确认选择”（禁用） | 单击候选卡仅使其成为选中项；不结算 |
| 已选卡，库内张数 < 容量 | “确认选择”（可用） | 单击后直接加入新卡、提交一次选择并离开；**不打开换牌页** |
| 已选卡，库内张数 >= 容量（包括被强制诅咒超容） | “确认选择”（可用） | 单击后直接显示交换弹层，**不允许直接加入**、不弹额外确认层 |
| 主页面“跳过” | “跳过” | 直接放弃本次选卡并结算，无中间结果页 |
| 返回的交换弹层 | 保留之前选中的新卡 | 允许重新选择三候选之一或跳过，牌库未变化 |

主页面底部**仅两个可点击决策按钮**：“跳过”和“确认选择”（“获取此牌”也可作为文案，但实现全项目统一一个词）。牌库“当前张数/容量”显示为只读信息，不是第三个“交换”或“加入”按钮。奖励候选始终从实际三选一数据绑定，允许少于 3 时居中显示。禁止通过图文提前揭示隐藏卡牌身份。

## 4. 满额交换弹层布局

**参考画布 1920×1080**；以下是版式起点，需在 Unity 1280×720 实机阅读后微调，不冒充已通过像素级验收：

- 继承 S05 的 Battle V05 背景/页眉；后方原奖励页做灰黑遮暗，默认不允许点击穿透。
- 居中纸面占可视区大部分，但保留四周背景轮廓：建议约 x=180..1740，y=160..960（宽约 1560、高约 800），避免再套一个全屏遮蔽的简单纯色矩形。
- 标题“交换卡牌”；副标题“牌库已满，请选择一张已有的牌与奖励牌交换。”；容量显示原值，例如 12/12。
- 左侧约 30% 宽：大幅新卡预览（正式现有卡框+插画+数据文案），区头“将获得的奖励牌”；中央单一交换方向指示，不做第三种决策控件。
- 右侧约 60% 宽：区头“选择换出的旧牌”，**4 列×2 行、每页 8 张**旧牌；卡面缩略仍可辨识，留出选中/禁用态轮廓；页码位于右侧网格下方，左右翻页，与主按钮区分；超出 8 张须分页，页数 = ceil(当前库内张数/8)，不少于 1。
- 底部两个并列操作：“返回奖励页”和“确认交换”；初始未选旧牌时“确认交换”禁用；旧牌选中后变为可用。点击旧牌**只选中，不立即交换**。
- **卡牌同名副本必须逐张独立**：缩略卡绑定原始 Library 下标、名字、强化/附加态，不能按卡名去重，提交按原始下标换出。诅咒可以显示但必须显著禁用且不可选；若全库无合法目标，允许返回并跳过。
- 翻页不清除已选的旧牌下标；换页后只有当前页可见项展示选择描边。若牌库数据在弹层打开后变化，提交前按 RunSession.CanAcquire 重新校验，不允许用过期下标替换另一张牌。
- 边框/深浅色、角色插画、背景只作为视觉衬托，**不要用低对比文字或密集排线覆盖卡名、效果和按钮**。

## 5. 交互状态机（无多余“是否交换”中间页）

~~~text
S05 三候选页面
  ├─ 点击候选 -> 只选中候选（可切换）
  ├─ 跳过 -> 直接完成奖励
  └─ 确认选择
       ├─ Library.Count < Capacity -> 新卡直接入库 -> 完成奖励
       └─ Library.Count >= Capacity -> 直接打开交换弹层
            ├─ 旧牌网格选择/翻页 -> 只改变待换出下标
            ├─ 返回奖励页 -> 取消弹层，不动牌库，保留三选一选中项
            └─ 确认交换（已选合法旧牌）
                 -> 原子替换一个旧库内实例 -> 完成奖励
~~~

成功确认后才提交；返回/跳过不得删旧牌；不重复发放；沿用 2026-10-24 “确认即离场、无领取结果页”裁定。候选 RNG / 卡牌稀有度 / 共鸣等仍依正式代码，不得由 UI 设计改变。

## 7. 实机验收（必须出截图/录屏）

1. 1920×1080 与 1280×720：主奖励三候选、满额换出弹层；大左卡、小右卡不重叠，8 卡显示，页码可读；滚动/低分辨率都不遮住确认与返回按钮。
2. 12/12 库：进入弹层后原奖卡被保留，右侧第 1/2 页（8+4）；第 2 页可以选中旧牌，翻回第 1 页再回第 2 页选择仍在；旧卡被选中但未确认时无数据变更。
3. 未满库（例如 11/12）：确认后直接增加一张，无弹层；无重复追加。
4. 12/12：只在**确认交换**后替换一个明确选中的旧实例，库内总量不变；替换后旧卡附加状态不继承。
5. 交换弹层“返回奖励页”保持新卡选中，能切换候选或跳过；Esc/返回键同路，禁止背景透点。
6. 诅咒不可被普通交换，超容后仅允许合法替换，不准直接加入；无合法目标可退出。
7. 反复点击确认/跨帧关闭/重开均不发生重复发放、重复替换；不改随机数、存档及其他页面。
8. 对照 Battle V05 的纸张/配色/字体，确认**统一风格但不强迫复制全部战斗 HUD**。
