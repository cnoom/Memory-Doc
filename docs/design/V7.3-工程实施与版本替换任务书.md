## 2. 强制替换规范

1. 单一现行实现：不保留旧蓄步计数、字段、事件、旧卡效果、替代模式开关、旧版handler、无调用接口、注释掉的旧代码、兼容适配器或无意义枚举值。不要以空实现、obsolete 标记、永不成立的分支冒充删除。
2. 单一现行文档：原有设计文件按主题就地重写，去除过期段落、历史卡文/数值、旧流程图、历史对照附录、已完成任务记录和相互冲突的版本注记；仍有效的信息保留。仅保留当前开发所需正本和必要工程指南。完整卡表、遗物表、投放表、术语、存档规则和机器可读实现合同必须一致。删除被合并替代的稿件、更新目录与链接，不将它们搬到新目录。任务执行过程的证据放 PR、测试产物或仓外验证目录，不作为当前设计说明永久维护。
3. 存档：建议采用新版本标识并在入口明确拒绝不受支持的旧研发档；不维持旧效果引擎、废弃字段读取或历史ID映射。若确有用户数据保留义务，报告并获得单独裁决后才做最小迁移。不得删除用户本地存档、备份、未跟踪数据；保留文件不等于继续支持读取。现行ID可保持稳定但不为旧功能建立虚拟占位。
4. 清理必须跨域：C# runtime/editor/测试、JSON、ScriptableObject、Prefab/Scene、Addressables、序列化引用、Unity .meta、动画、UI、本地化、卡牌详情、AI/GUIACC、遥测、工具、样例及设计合同。去除旧用例，复用仍有效的断言并加强新规则测试。第三方库、Git历史、既有本地证据与当前任务无关的代码不在清理范围。
5. 允许临时分阶段候选验证，但最终提交不能包含多套生产规则或多份现行策划正本。测试夹具可在测试边界显式配置不同参数作对照，不得把废弃生产机制复制回主代码。基线测试使用固定旧Git提交/隔离worktree/独立Player，不在V7.3代码中保留V7.2分支。

## 4. 硬性验收门禁

- 实现扫描：旧机制独有的中英文术语、字段、类型、处理函数、事件、配置键、序列化名、历史卡效ID与旧测试名称按P0清单搜索；逐个核实命中语义。废弃机制真实残留数必须为0；通用单词（如合法Move、仍有效的蓄能水晶）不机械判定，必要时记录合法命中理由。不能仅凭 grep 无结果证明无序列化引用。
- 结构扫描：编译、Unity资源引用、Addressables/Prefab/Scene/.meta、一致性及冻结/废弃身份处理；不保留占位表、孤立资产或测试专用旧生产分支。
- 文档扫描：README、策划正本、实现合同、卡表、遗物表、词典和链接交叉核对；不存在仍声称蓄步生效、旧章节投放或旧数值仍适用的段落；删除所有迁移期冗余稿。检查过期规则及错误链接，而非仅全文查找版本号。
- 功能与数值：真实配对、状态源伤害、直接段与独立附伤、回合、死亡、整对消耗/返还、真实翻开次数、升级、Boss遗物、敌周期强化；首两战6/6、5/6、5/5对照、记忆0/50/100，视结果扩展25/75，真实奖励和地图机会、重复身份/混搭。自动化通过不代表趣味达标。选择最终值后删除临时生产候选，不保留旧开关。
- 交付报告：基线/候选SHA、变更/删除清单、剩余合法命中、引用及构建核验、测试输入与结果、已知风险；报告存PR或仓外证据目录。明确未执行或失败项，不因删除用例使测试总数下降而放宽覆盖率或验收标准。
