## 4. 场景与界面图层

战斗建议相对层级（从后到前，不是强制引擎数值）：背景 → 角色/敌人 → 战斗信息 → 卡牌框/插画/文字 → 公开状态覆层 → 详情 → 暂停暗幕 → 手记书体 → 手记内容 → 焦点与提示。局部层级可按实际架构调整，但角色不得遮挡读数，详情不得遮挡牌阵。

### 4.1 背景与立绘组合

- **V02 背景模式**：保留背景里原有角色，不再叠同一角色贴图。适合复现固定参考画面，不能通过隐藏 UI 来“移除”背景人物。
- **正式分层模式**：无人背景 + B01 学者 + 当前敌人独立贴图。切换敌人必须一起切换名称、生命、攻击、意图和阈值；背景不换人。
- 不对整张背景做不等比拉伸。按目标画面做等比裁切/留边方案，并复核主体安全区。源图实际尺寸以索引为准，不把它声称为1920×1080。
- 索引内已批准的独立人物是静态资产，不含全套攻击/受击/死亡动作；不能因一张贴图可显示而标记动作资源完成。

## 5. 卡牌与状态的正确合成

1. 牌形保持3:4。桌面显示144×192（1080p）或96×128（720p）。4×4格位固定；悬停/焦点只加轮廓，不放大或移位。
2. 卡框、插画和文字分层。正式使用C04/C05及其稀有度变体，逐ID读取索引spec中的window、windowMask与textSafe。按各自窗口遮罩，不沿用旧拱窗；框的外角也透明，**不能用所有 alpha=0 像素自动推断唯一插画窗口**。
3. 插画放在窗口后方，框在上方。正式打击/格挡/笔记插画为不透明骨白底，用于卡牌插画窗，不可当透明物件随意贴在背景上。物件主体优先 contain；需要 cover 时检查剑尖、盾边和羽笔是否被裁掉。
4. 卡名、类型、基础效果、完整词条由数据绑定。摘要与详情单独排版，不把大卡整图缩到96px宽。不要把每个同名实例重新生成一张图；升级默认复用插画。
5. 统一卡背不显示类型、稀有度、隐藏词条、病毒身份或随机磨损；不能记住并高亮玩家曾看过的隐藏牌位置。
6. 背面标记仅显示层数 `×N`，正面才显示具体加成。封锁仅限制配对，不禁点、不覆盖正文。顽固次数和迅速不预先显示在未知背面。
7. **格挡与护甲不同。** 格挡用盾形，护甲用胸甲等独立符号。打击单卡6伤害、格挡单卡6格挡只是策划条目示例；配对双方分别结算，不能把卡面数字误作整对总值。
8. 正面上限来自规则，不写死所有角色为1；学者当前稳定演示为1，其他能力/角色可能改变上限。能力牌按规则离场，持续图标进入玩家信息区。

| 图标/立绘 | 等比；不要为填满矩形改变宽高比。小图标需按32px实际大小检查 |

引擎无关导入要求：保留alpha、选择匹配源图的透明混合、不要反复预乘、不要把透明区RGB当可见底色。使用目标引擎现有UI导入规范配置颜色空间、过滤、压缩和图集；对文字边缘/墨线做实机复核后再开启有损压缩。SVG需要目标工程明确支持；否则使用对应PNG，不临时引入不受维护的运行时解析链。

若目标工程为 Unity：先确认其 UI 技术栈再映射 Sprite/UI图片与切片设置；清单的 `left,bottom,right,top` 与目标字段逐一对齐，不能复制旧按钮的52像素边距到新资源。图集打包旋转/裁边不得丢失锚点。不要把本仓库 `Assets` 的命名误认为已经带有正确 `.meta` 配置。

深墨PNG不能靠普通乘法tint变成骨白。深底图标应使用适配版、修改SVG颜色或以alpha遮罩着色。RGB全透明区的灰色不一定是可见光晕，要在真实深浅底合成后判断，不对整张图片盲目抠白/抠黑。

## 8. 交互与数据边界

- 按钮四态绑定真实可交互状态。禁用停止点击并提供原因；焦点独立可见。V05的装饰可以轻翘，卡阵不能跟着翘。
- 行动条段数与阈值来自敌人/阶段/修饰，不固定10格；显示当前值/阈值和距行动点数。临界不是现实时间倒计时，不写“还能翻N张”。
- 生命槽连续、行动条分段，不能把两种图形混用。增减数值按结算结果驱动，迅速/冰冻/击杀停止由规则触发，不由动画反推。
- 暂停时阻断背后牌阵输入、约束键盘焦点，关闭后合理恢复焦点；返回主菜单要走目标游戏既有流程，不复制预览“仅提示”的实现。
- `window.preview`、预览页中的常态/临界切换、切敌按钮、toast、演示 settings 不属于游戏UI。不得带进正式画面。设置应连接真实配置服务，减少动态关闭装饰性运动但保留换位必要信息。
- 详情按已确认的右栏布局避开牌阵；支持完整词条和长文案，查看本身没有行动代价。揭示/锁定等有文档分歧时，按功能规则来源逐项核对，不因美术接口未定就删玩法。

## 9. 开发 AI 推荐执行流程与验收

1. 读取目标工程约束与本索引，列出本功能使用的精确ID和候选依赖；复核当前用户确认范围。
2. 创建显式资源映射，核对文件存在、尺寸、hash、用途；只导入当前功能需要的文件。
3. 先实现层级、遮罩、锚点、字体和数据绑定，再接交互反馈。不截图切图替代已经存在的独立资源。
4. 以1920×1080、1280×720检查，再测目标工程实际窗口。小分辨率需要重排/字号适配，不只统一缩放整屏；超宽屏扩展场景，不拉伸牌阵。
5. 用真实数据检查：长卡名、多词条、多状态、标记多层、Boss不同阈值、长复合意图、禁用原因、零血/满血、设置焦点和暂停开合。
6. 保存常态/临界/详情/暂停截图，记录差异与尚缺资产；测试只证明技术正确，不能自动批准新候选。

验收至少包含：无双人物；属性区与立绘不重叠；卡阵不抖动；背面不泄露身份；遮罩不裁主体；无拉伸切角/书脊；字清楚且不烘焙；深浅底无异常透明边；输入不穿透暂停；正式UI无审阅控件。已有检查脚本只验证设计预览，不替代目标工程测试。
