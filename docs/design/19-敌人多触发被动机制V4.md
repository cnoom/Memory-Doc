# 敌人多触发被动机制 V4

> 裁决日期：2026-11-09  
> 状态：**正式设计规则；Unity 游戏仓已首轮接入 5 种代表敌人（哥林布为无被动对照），剩余 10 种待迁移。16 敌配置仍为首轮试玩建议，数值可调整。**  
> **规则优先级**：本文覆盖 [18·顺序入场预览与敌人被动位置干扰 V3](./18-顺序入场预览与敌人被动位置干扰V3.md) 第 3 节中“位置被动只能按手动翻牌计数或 Boss 阶段触发”和普通/精英固定 5/4 次的触发方案，以及 04/08 中将混乱、换位、洗牌固化为主动意图的旧设计。**不覆盖 18 第 2 节顺序入场预览**（1 秒展示、0.25 秒间隔、视觉与逻辑隔离仍有效），不改变 01 的牌阵、行动条、死亡即停、战斗副本或 15 的同名/异名共鸣基础规则。  
> 本文明确“被动”的完整含义是 `触发源 + 条件/阈值 + 效果 + 触发上限/重置方式`，不能把全部被动统一强制绑定行动条。

## 1. 设计目标与结构

**敌人 = 基础数值 + 主动意图 + 0～N 个被动。**

- **可以没有被动**：纯数值型敌人靠生命、攻击伤害、行动阈值或主动意图形成压力，不为凑齐机制而强加特殊效果。
- **主动意图**：敌人行动条满时执行，负责可预告的攻击、蓄力、防御和少数需要明确主动操作的特殊行为。位置混乱/换位/全桌洗牌不再默认占用主动行动。
- **被动**：在可选的事件条件成立时结算。默认普通敌人 0～1 个，精英 1～2 个，Boss 按阶段切换/增加但同时可见的复杂被动不宜超过 2 个（阶段变化本身可额外存在）。
- 玩家应能看到**被动名称、效果、何时触发、当前计数/进度以及触发上限**；与“下次行动意图”清楚区分。

## 2. V4 支持的触发类型

| 触发源 | 条件范式 | 事件语义 | 首轮用途 |
|---|---|---|---|
| 行动进度 | `行动条达到有效阈值的 50% / 75%` | 本周期由低于阈值跨到不低于阈值时触发；取 `ceil(有效行动阈值×百分比)` | 预告换位、污染、冻结 |
| 行动结束 | `每次行动结束` 或 `每 2 次行动结束` | 敌人本次主动意图已完整执行且双方存活时检查 | 放置病毒、复制桌面牌、累积护甲 |
| 无效翻牌 | `本周期累计 3 次无效翻牌` | 以符合 §2.1 的玩家手动失配次数计，不要求连续 | 对遗忘/失误施压的敌人 |
| 成功配对 | `本周期累计成功配对 2 组` | 每成功完成一组实际匹配 +1（不是按结算的两张牌各算一次） | 针对稳定配对的精英/Boss |
| 生命值条件 | `生命首次 ≤50%`，或 60%/30% 阶段切换 | 从未达成变为首次达成时立即标记待执行；默认整场一次 | 狂暴、阶段强化、记忆冲击 |
| 其他显式事件 | `玩家主动重铺` / `病毒被清除` 等 | 只在该事件实际发生时触发；必须逐条写明来源与限制 | 少数主题鲜明的特殊敌人，暂不大规模投放 |

### 2.1 无效翻牌的精确定义

- 仅计算玩家**手动**翻开有效背面牌，并且翻开时桌面至少已有一张可参与匹配的正面候选、最终没有成功配对的情况；一次手动翻牌最多计 1 次。
- **不计**：新批次首张纯探索翻牌（无正面候选）；入场预览及其自动翻回；效果自动翻牌；主动重铺；因死亡中断未完成匹配判定的操作；能力牌翻开后直接离场而未参与匹配。
- **概率共鸣失败不计入“记忆失误”**：如果此次有效尝试实际进行了异名概率共鸣骰，但因随机失败而无法匹配，不应额外作为玩家记错位置的惩罚。
- 不要求连续。计数默认每个敌人行动周期归零；如个别被动设为全场累积，必须在条目中显式写明。首次探索不受罚的口径优先于“每次没配上都算失误”。

### 2.2 成功配对的精确定义

- 每次真实配对结算成功，计为 1 组；同名与成功的异名共鸣均可计入。自动翻牌链中真实完成的匹配也可以计入，但预览绝不计入。
- “每 2 组”按完成配对的组数判断；不因一对两张牌而计 2 次。若某敌人要限定“仅手动导致的配对”，需单独声明参数。
- 被动不通过自身触发的效果递归重复计数；同一结算链达到多重阈值时受 §3 次数/队列限制。

### 2.3 行动进度与生命值条件

- 进度阈值按当前**有效行动阈值**计算，包含狂暴、Boss 阶段与遗物修饰；例如阈值 7 时 50% 节点为 4。
- 只有进入新的周期后才可重新触发本周期的进度型被动；减少行动条后再次跨过相同节点不会多触发。
- 玩家动作直接让行动条从阈值以下跨到满值、且同时跨过被动阈值时，**按时序处理：在敌人主动意图前完成已达到的进度被动，但不得打开新的玩家输入窗口**；为避免无预警的两次惩罚，若从 0 直接跳至满值等极端情况，默认只执行本周期第一个合格进度被动，其他溢出节点跳过。UI 显示整个预告刻度。
- 生命条件按现有伤害结算时点检测；一次伤害跨过多个阶段直接进入目标阶段，不逐段累计中间阶段效果。死亡即停优先。
- 特殊状态导致的有效阈值动态降低并跨过被动节点时，只产生一次待执行事件；不允许多次降低/恢复阈值刷触发。

## 3. 被动效果与公平性约束

### 3.1 可复用效果类型

| 效果类型 | 首轮实例 | 边界 |
|---|---|---|
| 位置交换 | 交换 2 张合格背面玩家牌 | 有清晰移动动画，不强制重新预览、不清除玩家已知信息 |
| 局部乱序 | 选择 3～4 张合格背面牌做可追踪循环换位 | 默认不允许无提示全桌乱洗 |
| 弱污染 | 向随机空位生成最多 2 张病毒牌 | 无空位则落空；不替换现有牌 |
| 强污染 | 先生成最多 2 张病毒牌，再将其中 1 张与 1 张合格玩家背面牌交换格位 | 必须**先成功生成至少 1 张病毒**，才能尝试随后的交换；否则交换阶段落空 |
| 冰封/封锁 | 选择 1 张合法牌施加状态 | 遵守既有合法性与解除时机 |
| 自身强化 | 获得护甲、提高攻击、降低行动阈值等 | 明示数值和持续期，防止无限堆叠 |
| 增生 | 向空位复制一张真实玩家牌 | 按 04 旧定义是真实战斗牌，不自动取得入场可见情报；上限需独立配置 |

### 3.2 病毒与换位严格规则

1. 每次污染按**当前空格**放入 `min(2,可用空格,病毒全场同时存在上限剩余额度)` 张病毒；首轮默认**同场同时存在最多 3 张**（不同敌人可配置，但不能默默绕上限）。
2. 对**新生成的病毒**执行交换：只从本次生成者选 1 张，与任意另一格中合格的**背面玩家牌**交换位置。不能选病毒/正面牌/稳定锚免疫牌，不能交换自己与自己；不足两个合法位置则交换落空，已生成的病毒仍保留。
3. 病毒本身**不享受正常玩家牌的顺序入场正面预览**；背面与统一卡背一致。交换只改变物理位置，显示清楚的轨迹，**不会**触发 `[翻开]`、`[翻回]`、`[入场]`、匹配与行动条。
4. 没有空位的强污染不会退化成“仅交换两张现有玩家牌”；因为该能力的设计依赖新病毒与旧牌位置交换。
5. 重铺时病毒被清除/移动的现有行为沿用战斗规则；不因为新被动改变 `[丢弃]`、`[离场]` 和 `[移除]` 的定义。

### 3.3 基础平衡与可读性

- 纯数值敌人可用更高 HP/攻击或较短行动阈值补偿无被动，但**幅度不先写死**；同章节、同牌库/种子比较玩家受到的实际伤害和翻牌压力后再校准。
- 「无效翻牌触发」最易惩罚新手：普通敌人建议至少累计 3 次才触发，每敌人行动周期最多 1 次，优先交换 2 张；不允许连续惩罚后瞬间触发再次洗牌。
- 「成功配对触发」有可能反向惩罚熟练玩家：优先交给精英/Boss，设较高阈值、明确预告、单周期上限，效果限小范围，避免无限连锁。
- 进度/事件被动都需要提示计数，位置被动必须让玩家看到卡牌移动的起止位置。UI 不展示未翻开的卡名或病毒身份。
- 同一敌人默认**每个行动周期不超过 1 次位置移动类被动**；其他非位置型可以独立触发，但不同时在同一操作链爆发大量效果。
- 不为“无被动”敌人强行配一个假被动，也不把「[急躁]/[连击]」这类已经由数值/意图清楚表达的性质机械重复登记为一个事件被动。

## 4. 统一事件和结算次序

事件来源只依赖战斗现有数据，不引入新玩家操作：

```text
玩家手动翻牌（预览不是动作）
  → 现有翻开/[入场]/[翻开]/配对/词条等完整结算
  → 收集本次 MatchResolved 或 InvalidManualFlip 等事件
  → 原规则推进敌人行动条，执行相关状态修饰
  → 收集 ProgressCrossed 及 HealthThresholdCrossed
  → 按事件顺序处理待触发的被动（死亡即停）
  → 若行动条满：执行本次主动意图
       → 若存活：触发 EnemyActionCompleted 被动
       → 结算行动条满状态、重置行动条、刷新下一意图/清周期计数
  → 结算需要的补牌/桌面稳定 → 顺序入场预览
  → 玩家恢复操作
```

**这张图描述事件组织，不擅自改变 01 中已有的十步翻牌细则。** 实现时事件可在原位置采集，涉及牌移动/污染的被动放入延迟效果队列，在原结算链安全点应用，避免修改正在遍历的牌集合；不得让新被动提前破坏本次匹配判定的候选集。其结果对下一次玩家操作生效。

- 事件排序：死亡中断最高；其次实际配对/无效翻牌事件；随后行动进度；随后敌人行动及行动后事件；阶段条件在造成伤害的当下标记，在最近安全点执行其效果。具体细节应由 Unity 实现测试固化。
- 每条被动显式包含 `oncePerCycle` / `oncePerBattle` / `everyN` / `cooldownCycles` / `maxOnBoard` 等限制；默认次数限制本周期 1 次。阈值达到但因候选不足落空，也视为已经尝试过，不欠账。
- 同一被动的副作用不再次直接触发自身；若被动造成伤害、死亡或牌区变化，按现有事件管线处理，但强制限制同链连锁深度与触发次数，不允许无限递归。
- 位置移动和病毒入场的动画期间锁定操作，预览逻辑与 18 第 2 节一致。随机来源从战斗种子派生，保证保存/读取和同种子回放一致。
- **特殊失败路径**：被动生成病毒前检测空位；新病毒不足 1 张时跳过交换；无合法背面玩家牌时跳过交换；在敌人已经死亡后不得出现已排队尚未执行的换位。

## 6. 实现接口与 UI 建议（非代码承诺）

建议事件源枚举：`ProgressCrossed`、`EnemyActionCompleted`、`InvalidManualFlip`、`MatchResolved`、`HealthThresholdCrossed`、`SpecialBattleEvent`。所有事件附 `battleId`、`enemyId`、`cycleIndex`、`sourceActionId`，匹配事件附 `pairId`，用于幂等去重。

示例数据结构：

```json
{
  "passiveId": "corrupt_swap",
  "trigger": {"type": "ProgressCrossed", "ratio": 0.5},
  "conditions": [{"type": "EnemyAlive"}],
  "effects": [
    {"type": "SpawnVirusInEmptyCells", "count": 2, "activeCap": 3},
    {"type": "SwapNewVirusWithPlayerBackCard", "count": 1, "requiresSpawned": true}
  ],
  "limits": {"maxPerCycle": 1}
}
```

UI：行动进度型在行动条上画刻度；计数型显示 `无效翻牌 2/3` 或 `成功配对 1/2`；行动后型显示 `下次行动后污染`；生命型显示 `生命≤50%：狂暴`。只显示玩家当前应决策的已启用规则，不公开隐藏卡面。

## 7. 首轮验收与优先顺序
