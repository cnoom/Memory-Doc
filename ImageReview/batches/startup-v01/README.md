## 启动流程建议

启动界面应只依赖最小启动包：纯色背景、徽记、小型必要字库；不能等待整套主界面资源加载完才显示Logo。加载必要配置、存档元信息、主菜单依赖和所需字体；具体资源集合由客户端确定，不阻塞等待全部战斗卡图。

显示后并行初始化。建议淡入250ms；从首次可见起最短停留约1秒，初始化已完成即可淡出250ms进入主菜单，不强制长时间等待。计时结束但资源未就绪则继续显示，不按固定计时强行进入。减少动态时可直接切换。加载完成仅切换一次，不允许重复初始化。

加载超过约2秒再显示“正在准备旅途…”（示意图展示该状态）；没有可信进度时不显示虚假百分比。初始化失败时保持本界面，改为可读错误提示与重试/退出入口；重试清理上次失败状态，保留可恢复存档，不静默覆盖。按钮可复用B03，失败分支必须另做布局验证。详细异常写日志，不向用户展示堆栈。

普通启动不设“点击开始”或“跳过”，自动转入既有主菜单；Logo页不播放战斗特效，不恢复背景输入。需客户端验证冷启动、快速加载、慢加载、失败重试、切换时无白闪。上述为交互提案，不是已实现的启动逻辑。
