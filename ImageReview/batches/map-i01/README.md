## 布局与交互

- 顶栏：游戏名、章节、金币、牌库、旅途手记。数值为示例。
- 左侧约20%：角色与生命、遗物列表、路线图例。图中头像和遗物仅为位置示意，正式拆分必须替换为已批准的学者与真实持有遗物资源，不能新增奖励定义。
- 中间约52%：起点1个、4层各4个内容节点、顶部Boss1个，共18个。由下向上推进，第3内容层含1个精英，第一层含战斗；商店、篝火、事件保底依05文档。
- 右侧约28%：当前选中节点类型、简短说明和“前往节点”。图中选择第二内容层左侧事件，不提前泄露随机事件或奖励。
- 当前节点为第一内容层第2个战斗。已完成路径用墨色实线，可前往路径用灰蓝虚线，未到达用浅灰虚线。当前位置和选中位置另加标签/双圈，不仅靠颜色。
- 点击可达节点先选中并更新右栏，再点击前往执行跳转；双击不隐式跳转。不可达节点可查看类型但前往按钮禁用并说明原因。键盘方向键移动焦点、Enter选中，确认按钮独立激活，Esc关闭详情或打开暂停。
- 连线由章节种子生成；每个节点向上一层邻近1—3节点连接，起点连第一层4节点，最上层4节点全部连Boss。示意图不作为实际随机种子或图数据。

## 检查与明确限制

已核对18节点、四层结构、精英所在层、三栏布局与输出尺寸。生成图部分路线仍带反向/双向小箭头，这是已知绘图瑕疵，不代表可以倒退；正式连接线统一不画箭头，以自下向上布局表达方向。后续拆分须程序化绘制准确路线和节点状态，替换示意头像及遗物，保留纸层和边缘版画。UI文字、节点、路径均需独立，不应把整张示意图作为游戏地图。
